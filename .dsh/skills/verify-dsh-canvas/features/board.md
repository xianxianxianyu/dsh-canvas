# Interactive board, data and write path

The agent creates a JSON Canvas `.canvas` file, changes it with `edit`, and uses `canvas_check` to validate it and see a composite PNG. The person opens the presented file in the interactive board tab: positioned notes, embedded diagrams, Markdown and images, groups and labelled edges. The owner-only board route applies small operations without rewriting untouched elements. DSH 0.2.2-rc.1 defaults `fs-observation-policy` off: independent text hunks preserve route geometry, but a stale whole-file `write` can lose it. A bounded host-memory journal detects retained intent; the tab offers explicit reapply or dismiss, not overwrite prevention. Optional policy-on stale guards remain a separate temporary-patch check.

## Sub-features

- `board-check`: malformed JSON or invalid board data produces `isError` with line, column and source excerpt; a good board passes with node and edge counts. `image: false` validates without rendering a PNG.
- `board-composite`: a normal check attaches a PNG with the board's positions, sizes, embedded diagram SVG, Markdown notes, image and labelled edge. The agent and the verifier both look at that actual PNG.
- `board-route`: unauthenticated GET and POST are HTTP 401; the owner POST accepts `{ sessionId?, path, ops }` and returns a version and one status per op, in order. Owner GET with `path` (and `sessionId` for a relative path) returns `{ lost: [{ id, at, ops, count }] }`. Absolute paths need no session id.
- `board-decline`: owner POST `{ sessionId?, path, decline: [batchId, ...] }` accepts the overwrite and removes only those batches from the host journal. It returns `{ declined: [...] }`; replaying absent ids succeeds without file writes. `ops` and `decline` are mutually exclusive, zod-validated requests on the same owner-only route.
- `board-ops`: `place`, `addNote`, `setText` (with `ifText`), `addEdge`, `removeEdge`, `removeNodes` report `applied`, `unchanged`, `missing` or `conflict`. Moving a canonical single-line node changes only that line. Replaying the same batch changes neither the file nor its version. Removing nodes also removes incident edges.
- `board-invalid`: a route operation against an invalid source returns HTTP 409 `invalid-source` with diagnostics and leaves every byte untouched; after repair, the same operation works.
- `board-edit-default`: with policy off, read → route placement → independent stale-view `edit` leaves both the new geometry and agent text present, without an intervening re-read.
- `board-lost-write`: with policy off, read → route placement → stale whole-file `write` loses geometry. `canvas_check` in that same host warns, and owner GET exposes the lost batch for recovery.
- `board-stale-guard`: with policy on only through a throwaway patch, both stale `edit` and overwriting `write` fail with `FS_STALE_VERSION` before any re-read. Re-read and `edit` then preserve both changes.
- `board-journal`: only applied operations enter the last 20 active batches per canonical board, held in that host's memory. Newer successful operations supersede only supplied fields: a drag removes old x/y intent, but omitted width/height stay under the resize's original batch id and time. Recovery accepts these partial placements. Only dry-run `applied` counts as lost; text conflicts, missing targets and unchanged intent are excluded. Restart and eviction lose recovery history.
- `board-tab`: the present card opens a real `.canvas` tab, not the text renderer; pan, zoom and fit keep JSON Canvas geometry. Nodes use sandboxed shared pages; the edge curve, ends and label position come from the same `scene()` as the composite PNG.
- `board-gesture`: drag-end sends one rounded `place` (no per-frame writes); resize-end sends one rounded `place` including size. Double-click blank space adds a Markdown note, double-click a text note edits with `ifText`, dragging between side dots creates an optionally labelled edge, Delete removes selected nodes/edges.
- `board-feedback`: each operation displays `applied`, `unchanged`, `missing` or `conflict`; busy retains the exact batch for an explicit retry. Invalid JSON replaces the editor with read-only line:column diagnostics and a fix-file hint; repair automatically restores editing. Missing files show not-found, not an empty editable board.
- `board-authority`: DSH file-resource changes re-read the complete file, replace all local positions and refresh embedded dependencies; a response from an older read cannot replace a newer file.
- `board-recovery`: lost batches list time, count and localized human descriptions (zh/en), preferring labels and file names to ids. 重新应用 resends the same ops. 忽略 accepts the overwrite through `board-decline`; after success GET, every tab and same-host `canvas_check` no longer report those batches. A failed decline keeps the choice visible. Neither silently replays intent; agent-facing check text retains exact operation JSON.
- `board-concurrent-drag`: while the pointer is down, the agent edits a different node; after release both changes survive and the tab shows the file's new geometry/text.

## How to get to it (user POV)

- Ask the agent to load `canvas-board`, create, check and present a `.canvas`. Open its 在侧边栏预览 card action. Drag nodes, select one and resize its corner, double-click blank space for a note, connect side dots, or press Delete. Double-click an existing text note to edit its Markdown.
- Every edit goes through `POST /api/canvas/board`, not a replacement of the entire file. Agent changes to an existing board use small `edit` hunks.
- After a deliberately destructive stale write in this test, the same-host `canvas_check` warns and the tab describes the lost changes. Choose 重新应用 to restore them or 忽略 to accept the overwrite and retire that intent from recovery.
- Board comment authoring is deliberately not exposed. Diagram comments still work; board edge anchors, pins, drift and PNG outlines need a complete separate interaction contract.

Never commit it. Record the doctor's effective `fs-observation-policy` report: the default-off journey expects off, which is a warning rather than a readiness failure. Do not enable it in the plugin patch or either profile.
- Set `run=$OUT/<run>` and create `$run/work`. `ROUTE` means `node $SKILL/scripts/board-route.mjs`. Open a session with `tab = await ui.open(browser, { url, run })`; drive its agent with `ui.send`. A headless alternative must mount the route server in that very host and keep it alive for the whole sequence; the stock runner does not do this.

## Gotchas

- Never re-read or check a board between the route write and its first stale-view tool attempt. Keep the route's geometry and the agent's text change independent so a source-match failure cannot masquerade as a version guard. In the policy-on pair, preserve both failures before allowing either re-read.
- `board-route.mjs` prints the response verbatim, including per-op statuses. HTTP 200 is not proof every operation applied; inspect each status. Owner GET exposes only lost retained intent, not a complete operation history.
- Policy off is the installed default, not a readiness defect. Hunk edits use current content; whole-file writes can still lose it. Neither the route's conditional write nor the journal prevents a later unguarded whole-file replacement.
- The journal is host-local memory, bounded to 20 active applied-operation batches per canonical board. A different process, a restart or an evicted batch cannot warn about or restore that history. A valid loss check must show the actual geometry loss and the warning/GET result in the original host before teardown.
- Newer successful user geometry/text/existence intent supersedes older intent. Only still-active operations whose dry-run result is `applied` count as lost; `missing` and `conflict` are not safe automatic recovery instructions. The journal is not durable undo or a complete audit log.
- A failed source parse refuses the entire batch. A valid source with a missing/conflicting operation still applies other operations; these are different contracts.
- The route does at most three stat/read/apply/conditional-write rounds. Its races, `busy` outcome and negative control are deterministic unit checks; live stale-view evidence does not by itself prove every interleaving (unit 4b models those).
- Only canonical one-element-per-line input promises a one-line move. Untouched member spans survive byte-for-byte, including prototype-named keys, multiline values and numeric spelling; they are not reserialized through JavaScript numbers.
- A repeated old `addNote` after an intentional deletion can recreate it (no tombstones). Absolute `place` operations intentionally replace the same geometry fields; `setText` alone carries a field-level precondition.
- Temporary `--patch` overlays do not change the committed plugin patch or profile defaults. Stop the patched server after its journey; never leave a globally enabled policy behind as a supposed fix.
- Interactive snapshots use `[data-canvas-board]`, `.react-flow__node[data-id]`, `.react-flow__edge[data-id]`, `[data-canvas-board-editor]`, `[data-canvas-board-status]`, and `[data-canvas-lost]`. Use the helpers for real pointer gestures; synthetic React-handler calls are not live verification.
- Pan and zoom change only the view, not file coordinates. Deltas passed to pointer helpers are screen pixels; compare file values with the measured viewport scale rather than assuming 1:1.
- The readonly render endpoint accepts the just-read source and returns content only. It never writes or changes the loss journal; Markdown remains host-only. Iframes have an empty sandbox and no network permissions.
- 忽略 is a host-journal decision, not a local filter: the owner POST removes selected retained batches, idempotently by id, without editing the file. A later GET or check cannot re-report them. A genuinely new user operation has a new batch id. Host restart/eviction also loses recovery history; neither is durable undo.
- A structurally valid board with a bad embed remains editable and shows the embed diagnostic; only invalid board source disables editing. Source repair, deletion/recreation, and embedded-file changes must refresh through DSH resources.
- Puppeteer's `mouse.click` needs `{count:2}` for the complete double-click sequence; `{clickCount:2}` alone did not emit `dblclick` in the installed harness. A missing editor is not permission to type into another control.
- An edge midpoint can be covered by a node. Check `elementFromPoint(...).closest('.react-flow__edge')` and the selected edge id before Delete; counts alone can pass after deleting the wrong node and its incident edge.
- Wait for the exact rounded file coordinates, not just a prior `applied` status: an optimistic fractional box can still be on screen while the successful write's authoritative re-read is arriving.
- A node iframe is keyed by its prepared document, not geometry. Chrome mounted tests caught a zero-layout inner document during initial srcdoc replacement; the new document gets a new frame, while dragging/resizing keeps its frame and only resizes it.
- Shared UTF-16 bounds are checked before editing: ids ≤200, note text and `ifText` ≤20,000; newly authored edge labels ≤500. Non-finite JSON numbers and nesting beyond 128 containers (including extension metadata) are located errors and route HTTP 409.
- PNGs must fit 1302² pixels and a 4096 px longest side, including rounding. A board that cannot fit at 0.01× gets an explicit size reason without Chrome capture. Span >16,384 px or isolated-node gap >8,192 px produces located warnings. Rendering has a 15-second deadline and releases its browser user/context on cancellation.
- Image embeds share a 24 MiB data-URI budget per page, including base64 overhead and repeated nodes; the per-file limit remains 8 MiB. Over-budget nodes become reasoned placeholder cards with warnings; later smaller images can still fit.
- Loss inspection follows board versions, not idle polling; source-identical inspections use the host cache. For responsiveness checks, retain native Resource Timing for actual POSTs and independently time an unrelated comments GET, checking status and final disk bytes. Browser JavaScript scheduling around hundreds of iframes is not host-route latency.
- Wait for the settled recovery text after a drag, not merely a pre-existing lost banner. Resize-only recovery must name width/height under the old resize time, not include a later drag's coordinates.
- DSH keeps inactive board tabs mounted. `ui.board` selects the visible root; do not count hidden tabs or dump every iframe's base64 source into the evidence log.
